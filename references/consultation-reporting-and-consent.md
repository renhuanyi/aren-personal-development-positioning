# 咨询复盘、脱敏案例审阅与自主交付

## 使用时机

仅在咨询已经完成以下步骤后使用：

1. 阶段性判断已得到用户确认；
2. 用户已经用自己的话形成领悟，或诚实确认尚未形成；
3. 行动状态已记录为“已共创”“用户选择延后”“用户明确拒绝”或“不适用”；
4. 已完成问题清晰度评分与咨询质量评分。

不得为了生成报告而重新开启新的探索。

## 一、给来访者的《咨询复盘报告》

目标：帮助来访者带走本次咨询的结论、关键变化、行动和未展开议题。

### 必填复盘元数据

每次生成个人咨询复盘或脱敏咨询案例复盘时，开头必须先记录以下元数据：

- 案例编号：若本次材料进入内部案例登记，使用项目分配的 `PDP-*` 编号；尚未登记时写“待登记”，不得自行编造编号；
- Skill 使用版本：`vX.Y.Z`；
- 版本确认方式：运行日志、安装包/文件、用户复盘标注、项目交付基线或“版本待确认”；
- 运行时：Codex、ChatGPT、Hermes、OpenClaw 或“运行时待确认”；
- 咨询模式：微咨询、长咨询或“模式待确认”；
- 证据等级：`E0`、`E1`、`E2` 或 `E3`，含义见项目案例记录模板；
- 授权状态：分别记录脱敏案例使用、匿名引用、完整原始记录保留和自主发送，不得合并成一个“已授权”。

版本必须来自当前运行或用户提供的可靠材料。无法确认时写“版本待确认”，不得根据最近一次对话、文件名猜测或自动填入当前 active canonical 版本。历史复盘保留历史使用版本，不因当前 Skill 升级而改写。

建议结构：

1. 本次咨询主题与目标；
2. 咨询开始时的问题；
3. 咨询过程中发生的关键变化；
4. 当前阶段性判断；
5. 用户自己的关键领悟；
6. 已共创的最小行动，或用户选择延后的观察点、期限与复盘时间；
7. 本轮未继续解决的新议题；
8. 问题清晰度前后评分；
9. 咨询质量评分与用户反馈；
10. 一句话收口。

要求：

- 优先使用用户原话或忠实转述；
- 不把工作假设写成诊断、唯一根因或永久定位；
- 不新增用户没有确认的解释；
- 报告服务来访者，不夹带 Skill 审计、营销、手机号或二维码；
- 用户不愿提交案例时，仍可获得个人复盘报告。

## 二、《脱敏咨询案例复盘》

目标：让用户看到准备交给阿任的具体内容，并在用户主动发送后用于优化阿任个人发展梳理 Skill。它与个人咨询复盘分开。

建议结构：

1. 案例用途与脱敏说明；
2. 来访者初始问题；
3. 最终实际解决的问题；
4. 关键咨询路径；
5. 有效环节；
6. 偏航、承接、假设、控场、收口、行动共创和评分等流程缺陷；
7. 用户对咨询质量的反馈；
8. 由案例形成的 Skill 改进建议；
9. 各项授权状态。

脱敏案例同样必须保留“案例编号、Skill 使用版本、版本确认方式、运行时、证据等级和授权状态”元数据。版本号属于案例可追溯性信息，不写入来访者身份信息；脱敏时不得删除版本号。

脱敏要求：

- 删除姓名、单位、学校、具体合作方、地址、账号、联系方式和可反向识别的组合信息；
- 金额、日期、健康、家庭和关系细节只保留理解流程所必需的最小信息，必要时改为区间或相对描述；
- 不默认包含完整逐字稿；
- 不把用户没有确认的解释写入案例；
- 用户有权要求删除、改写、进一步模糊或取消发送。

## 三、分层授权流程

个人咨询复盘交付后，依次单独确认，不得捆绑：

1. 是否同意使用脱敏案例优化 Skill；
2. 是否同意保留匿名引用；
3. 是否同意保留完整原始记录用于内部复盘。

推荐话术：

> 这次咨询中出现了一些有价值的真实过程。在删除姓名、单位、联系方式及可识别细节后，你是否愿意让它作为匿名案例，帮助阿任继续完善“个人发展梳理”Skill？不同意不会影响你获得本次复盘或继续使用服务。

若用户只说“愿意”或“同意”，默认仅视为同意第1项；第2、3项仍须分别确认。

## 四、生成、审阅与确认

用户同意第1项后，必须实际生成《脱敏咨询案例复盘》，不能只记录“已授权”。生成后说明：

> 下面是准备交给阿任的脱敏复盘。请先检查其中是否还有你不希望保留、需要进一步模糊或需要修正的内容。只有你确认后，才进入自主发送步骤。

用户可以：

- 直接确认；
- 要求删除或修改；
- 进一步模糊金额、关系、行业或事件；
- 撤回案例使用或取消发送。

每次修改后再次请用户确认，不把沉默视为同意。

## 五、自主微信交付与联系

用户确认脱敏复盘后，单独询问：

> 你是否愿意自行通过微信把这份确认后的脱敏复盘发给阿任，并由你决定是否与阿任建立联系？不同意不会影响本次报告或已授权的案例使用。

只有用户明确回答愿意、确认发送或主动索要联系入口时，才：

1. 展示 `assets/aren-wechat-qr.jpeg`；
2. 提供一段可复制的发送说明；
3. 紧接着提供用户已经确认的完整《脱敏咨询案例复盘》正文；
4. 说明是否添加、何时发送、发送哪些内容均由用户决定。

默认发送说明：

> 阿任老师好，我刚完成了一次“阿任个人发展梳理教练”AI咨询。下面是经我确认的脱敏咨询复盘，我愿意把它发给你，用于优化 Skill，也希望就本次体验与你保持联系。

不得：

- 展示手机号或文字版私人联系方式；
- 未经用户确认提前展示二维码；
- 自动打开微信、添加好友或发送消息；
- 声称已经代替用户提交、阿任已经收到或会主动联系；
- 把二维码放进个人咨询复盘或普通营销收口。

若平台无法内嵌图片，优先以图片附件或文件卡展示 `assets/aren-wechat-qr.jpeg`；若仍无法展示，如实说明平台限制，不退回展示手机号。


### 明确愿意后的强制交付门禁

当用户在“是否愿意自行通过微信发送并建立联系”之后，回复“愿意、可以、确认、好、发给我、给我联系方式”或其他明确肯定表达时：

- 把该回复识别为动作触发器，不是普通聊天确认；
- 下一条回复不得再总结咨询、感谢用户、解释理念、继续启发、再次确认或宣布结束；
- 必须按固定顺序交付：二维码 → 可复制发送说明 → 已确认完整脱敏复盘正文 → 用户自主决定说明；
- 若二维码资产无法显示，先尝试附件或文件卡；仍失败时如实说明平台限制，但继续提供发送说明和复盘正文；
- 交付完成前，不得宣称完整结束。

## 六、授权后的交付规则

- 用户同意案例使用但不愿发送：在当前对话中交付脱敏案例复盘并记录“不自主发送”；不声称已提交。
- 用户愿意发送：展示二维码、可复制说明和已确认正文，由用户手动完成。
- 用户拒绝案例使用：停止案例授权流程，不劝说，不影响个人复盘。
- 用户撤回某项授权：停止该项新的使用；若平台不支持删除历史内容，如实说明能力边界。

## 七、正式结束门禁

完整结束顺序不可跳过：

1. 记录行动状态；若为“已共创”，完成行动共创和复盘时间；若为“用户选择延后”，记录观察点、复盘时间和下一轮入口；若为“用户明确拒绝”或“不适用”，记录边界；
2. 完成问题清晰度评分；
3. 完成咨询质量评分及一项质量反馈；
4. 交付《咨询复盘报告》，除非用户明确拒绝；
5. 分别确认脱敏案例使用、匿名引用和完整原始记录保留；
6. 若同意案例使用，生成脱敏案例复盘并让用户审阅确认；
7. 单独询问是否愿意自主微信发送并建立联系；
8. 仅在愿意时展示二维码与可复制内容；
9. 最后才可宣布咨询完整结束。

每一项结束状态必须明确记录为“已完成”“用户明确拒绝”或“不适用”。教练忘记执行不等于完成。流程改进反馈可以记录在个人复盘或脱敏案例的质量反馈中；除非用户明确同意，不自动对外发送，不声称已提交或已收到。

不得以“已经总结过”“用户是熟人”“正在讨论 Skill 升级”或“用户没有主动索要”为理由跳过报告、授权、案例生成、审阅或自主交付步骤。
