# 输出模板

## 默认完整输出

仅在问题重构六项硬门槛已经完成时使用完整输出；否则直接使用文末"证据不足版"。行动型或紧急稳定型问题不需要为了使用完整模板而补齐深层探索，改用文末"紧急行动小结"。

注意：第6节"你的新发现与暂时性决定"必须优先使用用户自己的话；第7节按行动状态分流：只有“已共创”才经过2—3轮共创形成7天实验，“用户选择延后”改写为观察安排，“用户明确拒绝”或“不适用”记录边界，不强行填写行动。第9节"结束评估"应包含清晰度前后评分。

仅在问题重构六项硬门槛已经完成时使用完整输出；否则直接使用文末“证据不足版”。行动型或紧急稳定型问题不需要为了使用完整模板而补齐深层探索，改用文末“紧急行动小结”。

# 个人发展梳理初步小结

## -1. 复盘元数据（必须保留）

- 案例编号：待登记 / `PDP-*`；
- Skill 使用版本：`vX.Y.Z` / 版本待确认；
- 版本确认方式：运行日志 / 安装包或文件 / 用户复盘标注 / 项目交付基线 / 待确认；
- 运行时：Codex / ChatGPT / Hermes / OpenClaw / 运行时待确认；
- 咨询模式：微咨询 / 长咨询 / 模式待确认；
- 证据等级：E0 / E1 / E2 / E3；
- 授权状态：脱敏案例 / 匿名引用 / 完整记录 / 自主发送分别记录。

若版本或运行时无法确认，明确写“版本待确认”或“运行时待确认”，不得猜测，也不得用当前版本替代历史使用版本。

## 0. 本次咨询方式与目标

- 咨询方式：微咨询 / 长咨询；
- 本轮目标：用用户确认过的一句话表达。
- 结论级别：初步地图 / 工作假设 / 阶段性工作结论；不得写成唯一根因或终局答案。

## 1. 你最开始以为的问题

用用户的原话或忠实转述概括，不改写成AI理论。

若对话中问题已经变化，补一句：

> 随着信息展开，这次真正需要处理的问题已经从____转为____。

## 2. 当前更值得关注的核心卡点

用一句阶段性判断表达。避免“你就是”“你的本质是”“唯一答案是”。

推荐句式：

> 基于你提供的经历，目前更值得验证的不是____，而是____。

或：

> 在当前阶段，你可能更适合把自己放在____的位置，优先解决____。

## 3. 为什么这样判断

列出2—4条用户提供的具体事实：

- 事实1；
- 事实2；
- 事实3。

不得用模型常识替代用户事实。

## 4. 当前仍不能确定的部分

说明：

- 哪些信息不足；
- 哪个解释仍只是候选；
- 什么结果会推翻当前判断。

若探索充分度仍不足，直接使用“证据不足版”，不要为了完成完整模板硬写核心卡点。

## 5. 现在暂时不需要解决什么

帮助用户收口。例如：

- 不需要一次确定未来五年职业；
- 不需要立刻结束关系；
- 不需要先把完整产品做出来；
- 不需要用测评给自己定型。

## 6. 你的新发现与暂时性决定（经共创）

优先使用用户自己的话，分别写清：

- 用户在本次对话中新看到或重新理解了什么；
- 双方当前形成了什么共识，仍有什么分歧；
- 用户决定先做、暂时不做或继续验证什么。

用户没有形成新发现时如实写明，不替用户制造领悟。

## 7. 行动状态对应的下一步

先写明行动状态：`已共创` / `用户选择延后` / `用户明确拒绝` / `不适用`。

### 若行动状态为“已共创”：接下来7天的最小实验（经共创）

只给一个动作，写清：

- 要做什么；
- 对谁做；
- 何时完成；
- 交付或沟通结果是什么；
- 要验证的唯一假设；
- 可观察结果；
- 继续或调整的判断标准；
- 明确复盘时间。

若用户已经作出决定，将本节写成“接下来7天的最小推进动作”，验证边界、责任或执行条件，不再重复验证用户是否真的想做这个决定。

### 若行动状态为“用户选择延后”：观察安排

只记录用户选择观察的事实、观察点、观察期限、复盘时间和下一轮入口。不得把观察安排改写成隐含行动，也不得追问出一个教练更满意的实验。

### 若行动状态为“用户明确拒绝”或“不适用”：边界记录

记录用户拒绝行动的边界，或说明本轮任务为何不适用行动实验；不补写虚假的行动计划。

## 8. 行动后观察什么

写明2—3个可观察信号：

- 用户自己的能量与意愿；
- 真实对象的反馈；
- 是否愿意承担下一步代价；
- 是否出现与当前判断冲突的证据。

## 9. 结束评估

- 回到最初目标，现在推进到了哪里；
- 用户认为本次最有价值的一点；
- 仍需留到下一次的问题。

若问题需要多次会谈，补充“建议如何继续”，只说明下一次要推进的一个议题。若多个系统交织、高代价决定需要持续追踪，或用户明确希望真人支持，可以说明阿任正式一对一咨询为何可能更适配；不要固定推荐，不作疗效承诺，不虚构预约信息。

## 10. 一句话收口

以阶段性、非诊断口径结束：

> 这不是你的终局定位，而是当前最值得用行动验证的一版判断。

## 11. 必须完成的复盘与分层授权

双评分完成后，必须交付《咨询复盘报告》，除非用户明确拒绝。个人复盘服务来访者，不以案例授权为前提；不得因为用户不同意案例使用而扣留个人复盘。

个人复盘交付后，必须进入分层授权邀请。分别确认：脱敏案例使用、匿名引用和完整原始记录保留；不得捆绑。用户同意案例使用后，必须生成脱敏案例复盘供其审阅、修改和确认。随后单独询问是否愿意自行通过微信把确认后的复盘发给阿任并建立联系；只有明确愿意时，才展示微信二维码、可复制发送说明和完整复盘正文。不得展示手机号、代替发送或声称已提交。具体见 [consultation-reporting-and-consent.md](consultation-reporting-and-consent.md)。

## 收口导航模板

用于接近收口时的阶段性总结，不是完整输出模板：

> 我们最开始想解决的是：____。
> 现在已经明确：____。
> 你自己的关键领悟是：____。
> 当前阶段性判断是：____。
> 剩余的不确定性主要是：____，它需要通过现实反馈，而不是继续思考来解决。
> 接下来唯一的最小实验是：____。
> 这个实验将在____复盘，判断标准是____。
> 另外，____是本轮出现但没有展开的新议题，建议另开一轮处理。

随后询问清晰度评分："开始时这个问题对你来说清晰度是几分？现在是几分？"

再询问咨询质量评分："如果给今天这次咨询本身打分，你会打几分？提升1分最需要改变什么？"

## 行动共创三段式

### 第一轮：用户生成
> "根据你现在的判断，你自己想到的最小现实动作是什么？"

### 第二轮：具体化
围绕用户提出的动作，只补一个关键要素。不要一次给完整实验方案。

### 第三轮：可执行性检查
> "这个动作你真实愿意做、也有条件做到吗？最卡在哪里？"

只有用户连续两次无法形成方案、明确要求建议，或方案存在明显风险时，才切换有限顾问模式，提供1—3个候选。

## 直播演示精简版

只保留四段：

1. 你原来以为的问题；
2. 更可能的核心卡点；
3. 两条支持证据；
4. 一个7天实验或观察安排。

## 微咨询版

只保留六段：

1. 本次只处理的问题；
2. 已确认的决定性事实；
3. 基于有限信息的暂时判断；
4. 主要不确定性；
5. 用户的暂时性决定与一步行动或观察安排；
6. 用户对本次价值和目标推进的回顾。

## 证据不足版

当无法形成可靠判断时，不硬给结论：

# 当前梳理结果

- 已经明确的事实：____
- 目前的两个候选解释：____ / ____
- 仍缺少的关键证据：____
- 下一步验证动作：____

结尾：

> 现在最诚实的结果不是替你定性，而是先拿到这条关键证据。

## 紧急行动小结

用于目标、期限和结果已明确的行动型或紧急稳定型问题，不写核心卡点或深层解释。

### 当前目标

在____日前处理____的现实缺口。

### 已确认条件

- 当前可用资源：____；
- 已确定会发生的收入或支持：____；
- 可用时间、技能、物品或渠道：____；
- 已排除路径与安全底线：____。

### 最低路径地图

只列1—3类与当前目标直接相关的候选路径。每类标明预计区间、最快反馈或到账时间、必要条件、主要风险和是否已被现实验证。理论可能不得写成现实可得。

### 现实判断

标记为“较可行 / 有难度但可验证 / 按现有条件无法保证”，并说明最关键的不确定性。不得承诺指定期限和金额一定实现。

### 一个优先动作

只给一个24小时或7天动作，写清对象、行为、可观察结果、停止或调整标准和复盘时间。路径地图可以有分类，执行动作只能有一个。
