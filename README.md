# 阿任个人发展定位教练

一个用于 AI 助手的个人发展教练 Skill：帮助处于职业、创业或人生转换期的人，把混乱、卡住和说不清的状态，推进到一个可验证的判断和一个现实可做的下一步。

当前版本 **v1.9.2**，生命周期 **Observation（观察期）**。它已经在真实咨询中跑通过完整流程，但规则仍在根据反馈迭代，公开分享的目的是收集真实使用反馈。

本仓库就是 Skill 本体：根目录的 `SKILL.md` 是入口，`references/` 按需读取。它不依赖脚本、API、密钥或某个平台专有能力，可以直接安装到 Codex、Claude Code、OpenClaw、WorkBuddy、Hermes、ChatGPT 等支持 Agent Skills 约定的运行环境。

## 它适合什么

- 不知道下一步该做什么，或者几个方向互相牵扯；
- 长期卡住、动力不足、反复想却不行动；
- 创业还是回职场、要不要离开一段合作或一份工作；
- 现金流或债务压力正在影响发展选择；
- 合伙、家庭或工作关系影响了自己的发展判断；
- 想找人把一件事从头到尾梳理清楚。

## 它不做什么

- 不做心理诊断，不做危机干预；
- 不替代医疗、法律、财务或债务重组等专业意见；
- 不替用户做辞职、离婚、拆伙、投资这类不可逆决定；
- 不保证收入、不承诺疗效、不虚构预约渠道；
- 不把 MBTI、盖洛普这类测评当成命运结论。

## 一次咨询会发生什么

支持两种深度：

- **微咨询**：约 10—20 分钟，最多 6 个实质问题，围绕一个窄问题给出阶段判断和一步行动；
- **长咨询**：约 45—60 分钟，最多 10 个实质问题，完整走完背景、困惑、已有探索、期待四个部分。

两种深度都执行同一套流程：聚焦唯一问题 → 具体事件取证 → 阶段判断 → 行动共创 → 双评分 → 复盘与授权 → 正式结束。

过程中有三把锁防止跑偏：时间锁、问题轮次锁、状态锁。用户随时可以暂停、纠偏或结束；接近约定时间就不再开启新议题，缺少的证据如实标为待验证，不硬凑结论。

结束时会有两个独立评分：问题清晰度（咨询结果如何）和咨询质量（这次过程和教练表现如何）。两者不会互相替代。

如果一次对话只能形成问题地图，就如实收口到阶段结果；复杂议题建议分次推进，或者找真人持续支持。

## 安装

这是一个标准的 Agent Skills 目录，不需要额外封装或格式转换。把整个仓库克隆下来，放进目标 Agent 的 Skill 目录即可。

```bash
git clone https://github.com/<账号>/aren-personal-development-positioning.git
```

常见运行环境的放置位置：

| 运行环境 | 放置位置 |
|---|---|
| Codex | `~/.codex/skills/aren-personal-development-positioning/` |
| Claude Code | `~/.claude/skills/aren-personal-development-positioning/`，或项目内 `.claude/skills/` |
| OpenClaw | OpenClaw 的 AgentSkills 目录，注册 `SKILL.md` 为入口 |
| WorkBuddy | WorkBuddy 的 Skill 目录，注册 `SKILL.md` 为入口 |
| Hermes | 挂载或复制同一目录，以 `SKILL.md` 为入口 |
| ChatGPT | 自定义 GPT：`SKILL.md` 作为 Instructions，`references/` 作为知识文件 |

各运行环境的具体目录以该平台官方约定为准。安装后重启会话，Agent 会根据 `description` 判断是否调用；也可以直接点名使用。

运行环境相关的说明放在 `agents/` 目录：`codex.md`、`claude.md`、`openclaw.md`、`workbuddy.md`、`hermes.md`，以及给其他 Agent Skills 兼容运行环境的 `generic.md`。

## 建议怎么开始

用语音转文字，想到什么说什么，不需要提前整理，也不用修改口语重复和错别字。例如：

> 请用阿任个人发展定位教练陪我梳理。我现在有几个事情搅在一起，说不清楚，你先帮我聚焦一个问题，其他的一会儿再说。

如果已经有明确目标，可以直接说：

> 我想用长咨询的方式，聊清楚「要不要离开现在的合作」这件事。

## 反馈什么最有价值

- 它有没有让你觉得被理解，而不是被审问；
- 它有没有在问题接近解决时及时收口，而不是一直追问；
- 行动方案是不是你自己参与出来的，而不是被安排；
- 它有没有过早给出听起来很聪明的解释；
- 结束时两个评分你觉得准不准。

不需要格式，直接说体验就行。可以在仓库里提 Issue，也可以按 `SKILL.md` 里说明的方式联系作者。

## 目录结构

```
SKILL.md                     主指令文件，运行时入口
VERSION.md                   版本与生命周期
CHANGELOG.md                 公开变更记录
CAPABILITY_MATRIX.md         能力边界矩阵
AGENT_COMPATIBILITY.md       跨运行时兼容说明
openai.yaml                  平台元数据
agents/                      各运行环境的薄适配说明
references/                  流程、边界、质检、案例库等按需读取的参考文件
assets/                      图标与联系二维码
```

`references/` 采用按需读取：运行时只加载当前步骤真正需要的文件，不要求一次性全部读入。如果某个运行环境无法读取参考文件，应当如实说明，而不是自行补写。
